Part A · notebook 04f

The next-WORD model — it knows 31 whole words

This little model has a dictionary of 31 words. You give it a few words, it predicts the next word. That's the exact loop ChatGPT runs — just much, much smaller.

cell · the corpus
1 · A tiny pile of sentences to learn from

A real model reads a big chunk of the internet. Ours reads ~30 short, kid-friendly sentences that overlap a lot on purpose ("the cat …", "the dog …", "went to the …") so a tiny model can spot the patterns.

cell · vocabulary
2 · Give every word a number

The model can't do maths on the word "cat" — only on numbers. So every distinct word gets an id (a row number). We also add three helper tokens: <bos> marks the beginning, <eos> marks the end (it's how the model learns to stop), and <pad> is filler.

words  = sorted({w for s in sentences for w in s.split()})
vocab  = ["<pad>", "<bos>", "<eos>"] + words
tok2id = {w: i for i, w in enumerate(vocab)}     # word -> id
V      = len(vocab)

def encode(s):
    return [BOS] + [tok2id[w] for w in s.split()] + [EOS]

print("vocab size V =", V)
print("encode('the cat sat') ->", encode("the cat sat"))

cell · the model
3 · The model — five lines you've already met

Each row number flows through the same pipeline you built in earlier lessons: turn the id into a vector (embedding), add a position vector so it knows word order, let the words look at each other (attention) and think (feed-forward), then score every possible next word (head).

class NextWord(nn.Module):
    def __init__(self, d=32):
        self.tok  = nn.Embedding(V, d)        # word id  -> 32-number vector
        self.pos  = nn.Embedding(MAXLEN, d)   # position -> vector (word order)
        self.enc  = nn.TransformerEncoderLayer(d, nhead=4, dim_feedforward=64,
                                               batch_first=True)  # attention + thinking
        self.head = nn.Linear(d, V)           # vector -> a score for each word

model = NextWord()
print("parameters:", sum(p.numel() for p in model.parameters()))
output

4 · Teach it: predict each word from the ones before

The trick for making practice questions is beautifully simple. Take a sentence, and slide it by one: the input is everything except the last word, the target is everything except the first. So at every spot the model must guess the next word.

cell · the key trick
4½ · The "no peeking" rule (causal mask)

There's one rule that makes this a writer instead of a cheater: when guessing word #4, the model is only allowed to look at words #1–3. If it could peek at the answer, it would learn nothing useful. One line of code enforces it.

mask = nn.Transformer.generate_square_subsequent_mask(T)   # block looking right

Under the hood: each row may only look left (green = allowed)

Read a row left to right: the word "cat" (row 3) can see <bos>, the, cat — but not "sat" or "on", which come later. No spoilers.

cell · generation
5 · The actual ChatGPT loop

Now the payoff. To write text: run the model, take its guess for the next word, stick it on the end, and run again — feeding the model its own words — until it says <eos>. That's how every chatbot writes: one word at a time.

model.eval()   # clean, repeatable predictions

def generate(prompt, max_new=10):
    ids = [BOS] + [tok2id[w] for w in prompt.split()]
    for _ in range(max_new):
        logits = model(torch.tensor([ids]))[0, -1]   # scores for the next word
        nxt = int(logits.argmax())                    # pick the top word
        if nxt in (PAD, EOS): break                   # model decided to stop
        ids.append(nxt)                                # add it, then loop
    return " ".join(id2tok[i] for i in ids[1:])

for p in ["the cat", "the dog likes to", "she opened the", "i went to the"]:
    print(f"  {p:22s} -> {generate(p)}")

Part B · notebook 04g

The next-CHARACTER model — it knows ~25 letters

Same machine, one change: a token is now a single letter, not a whole word. With only ~25 letters it can spell any word — even ones it never saw. That open vocabulary is what "general purpose" really means.

cell · the corpus
1 · One long stream of text (not a word list)

A word model wants a list of sentences. A character model just wants text — one long string. We use 13 nursery rhymes (~1,900 characters) because they rhyme and repeat, so a tiny model can learn to spell and echo them.

CORPUS = """twinkle twinkle little star
how i wonder what you are

hey diddle diddle the cat and the fiddle

print(f"{len(CORPUS)} characters, {CORPUS.count(chr(10))} lines")

cell · vocabulary
2 · The dictionary is the alphabet

In Part A every distinct word got an id. Here every distinct character does — letters, the space, the newline. That's the whole dictionary: just 25 symbols. No start/end/pad tokens — we don't pad anything.

chars = sorted(set(CORPUS))
V     = len(chars)
stoi  = {c: i for i, c in enumerate(chars)}      # char -> id
data  = torch.tensor([stoi[c] for c in CORPUS])  # the whole text as numbers
T     = 64                                        # how many chars it sees at once

print(f"V = {V} characters: {chars}")

Because the alphabet is tiny and closed over letters, the model can spell any word built from them — even one that never appears in the rhymes. That's the whole point.

cell · the model
3 · The same model — now stackable

Almost identical to Part A's NextWord. Two small differences: the embedding table is 25 characters wide instead of 31 words, and we use nn.TransformerEncoder(..., num_layers=n) so we can stack layers later.

class CharGPT(nn.Module):
    def __init__(self, d=64, nhead=4, ff=128, nlayers=2):
        self.tok = nn.Embedding(V, d)            # char id -> vector
        self.pos = nn.Embedding(T, d)
        layer    = nn.TransformerEncoderLayer(d, nhead, ff, batch_first=True)
        self.enc = nn.TransformerEncoder(layer, num_layers=nlayers)  # stack!
        self.head = nn.Linear(d, V)              # vector -> score per character
cell · training data
4 · Slide a window, predict the next character

In Part A we padded each sentence. Here we just grab a random window of 64 characters as the input, and the same window shifted by one as the target. So the model learns t→h, h→e, e→␣ … the next character, everywhere.

def get_batch(bs=32):
    ix = torch.randint(0, len(data) - T - 1, (bs,))
    xb = torch.stack([data[i:i+T]     for i in ix])   # window
    yb = torch.stack([data[i+1:i+T+1] for i in ix])   # same window, shifted by 1
    return xb, yb

target:  t followed her to school one day whic

cell · the big idea
7 · Why this is "general purpose": the out-of-vocabulary wall

Here's the difference made concrete. Part A's word model had a fixed 31-word dictionary. If a word isn't in it, there is literally no id for it — the model can't even read it. The character model spells the same word from letters it already knows.

for w in ['cat', 'puppy', 'banana', 'dinosaur']:
    a = 'OK' if w in word_vocab else 'CANT READ IT'
    b = 'can spell it' if all(c in stoi for c in w) else 'missing a letter'
    print(f'{w:9s}  whole-word: {a:14s}  character: {b}')

Real GPTs use a clever middle ground called subword pieces: common words stay whole, rare ones get split into chunks (dino + saur), right down to single letters if needed. Best of both — short to read, but still able to spell anything.

cell · depth experiment

On Part A's easy toy, a 2nd layer did nothing. Spelling real rhymes from letters is genuinely harder, so depth now pays off. Same experiment, real result:

The 2-layer model is 34% better. The lesson: throwing more brain at a problem only helps when the problem is hard enough to need it.

The whole journey in one sentence. Both models run the same pipeline — embed → attention → think → score → pick. Shrinking a token from a whole word to a single letter is the one change that turns a 31-word memoriser into something that can read and write any word. That open vocabulary is the seed of "general purpose".
