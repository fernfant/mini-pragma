The same PRAGMA recipe applied to tabular data with realistic inter-attribute correlations. A bridge between the pets toy and the streaming churn predictor.

What's new vs prior lessons

  • 5-class classification (a step toward regression)
  • Realistic inter-attribute correlations in the data — beach houses tend to have pools, vintage houses are usually smaller, etc.
  • A more nuanced pre-train vs baseline story: pre-training wins when labels are scarce, baseline catches up at scale

The story is more nuanced than the streaming churn example:

  • 50 labels: pre-training wins. 7 percentage points on accuracy. When labelled data is scarce, the encoder's MLM-learned representations give the linear probe a head start.
  • 100 labels: still a small pre-trained edge.
  • 500-4000 labels: baseline pulls ahead. With enough labels, an end-to-end model can find better representations specific to the price-classification task.
Why isn't pre-training dominant everywhere? Tabular data has less rich contextual structure than sequential data. With 4000 labelled houses, end-to-end training can learn price patterns directly without needing pre-training's warm start. Frozen features are a hard constraint — the encoder can't be tuned to emphasise what matters for THIS task.

Real-world fix: instead of a frozen probe, use LoRA fine-tuning — unfreeze a small fraction of weights (~2-4%) during downstream training. PRAGMA does this (§3.1.2).

The data — with correlations this time

The key insight: without correlations between attributes, MLM has nothing context-dependent to learn. With correlations, the encoder learns the underlying structure (beach houses tend to have pools, vintage houses are smaller).

We define 5 house archetypes — each is a probability distribution over attribute values:

ARCHETYPES = {
    "rural_cottage": {
        "size":         {"small":5, "medium":4, "large":1, "huge":0},
        "neighborhood": {"downtown":0, "suburb":1, "rural":8, "beach":1},
        "pool":         {"nopool":9, "haspool":1},
        ...
    },
    "luxury_beach": {
        "size":         {"small":0, "medium":1, "large":4, "huge":5},
        "neighborhood": {"downtown":0, "suburb":0, "rural":0, "beach":10},
        "pool":         {"nopool":1, "haspool":9},
        ...
    },
    "urban_apartment", "suburban_family", "old_townhouse",
}

Each house is generated by picking an archetype, then sampling each attribute from that archetype's weighted distribution. The result is rich realistic structure for the encoder to learn.

The architecture (identical to pragma_mini)

class Encoder(nn.Module):

        ...

class PriceHead(nn.Module):
    """Pool the encoder output, predict price bucket (5 classes)."""
    def __init__(self, d=32):
        super().__init__()
        self.proj = nn.Linear(d, 5)
    def forward(self, h):
        pooled = h.mean(dim=1)
        return self.proj(pooled)

The encoder is reusable across tasks. Only the head changes per task. That's the foundation-model idea.

The pre-training (L4)

for step in range(3000):
    idx       = torch.randint(0, N_HOUSES, (128,))
    xb, yb    = mlm_mask(X[idx])             # mask 30% of value tokens
    h         = encoder(xb)
    logits    = mlm_head(h)
    loss      = loss_fn(logits.reshape(-1, V), yb.reshape(-1))
    opt.zero_grad(); loss.backward(); opt.step()

Higher mask rate (30%) than in other lessons. The reason: with more missing info per record, the model is forced to use surrounding context heavily — which is exactly what teaches it the inter-attribute correlations.

The price labels are never used here. This is fully self-supervised — the data labels itself.

Bridge to L5b

The pattern emerging: as data gets richer and more structured, pre-training's advantage grows.

In Lesson 5b the same recipe is applied to sequential event data (streaming sessions). There, pre-training wins much more decisively across ALL label counts — because the data has rich sequential structure (skipping patterns over time, narrow vs varied genre choices) that's hard for an end-to-end model to discover without the self-supervised warm-up.

PRAGMA's banking event streams are the extreme case where pre-training is essentially required. Tabular data: optional. Long sequences with subtle patterns: pre-training is the whole game.
