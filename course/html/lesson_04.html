The fill-in-the-blank game

Pick a sentence with a word missing. Have the model guess what was there. You don't need to label any data — the right answer is whatever word you hid.

If you have "The cat sat on the mat", you get 6 training examples from one sentence:

Masked inputAnswer
____ cat sat on the matThe
The ____ sat on the matcat
The cat ____ on the matsat
The cat sat ____ the maton
The cat sat on ____ matthe
The cat sat on the ____mat

Free training data! This is why BERT (and PRAGMA) can be trained on the whole internet without humans labelling anything. The fancy name is masked language modelling (MLM).

Why? So what is masking actually FOR?

This is the question that trips everyone up. We're not masking because we want to fill in blanks — we're masking to manufacture a training task out of regular text. Look at the chain:

  1. We have a pile of plain text — Wikipedia, books, banking events — with no labels.
  2. We can't train without a "right answer" to grade against. Where do we get one?
  3. Trick: hide a word ourselves. Now we have a training example: input = the sentence with a blank, answer = the word we hid. The model never sees the hidden word during the guess.
  4. That gives us as many training examples as we want, from any text, automatically.

What does "hide a word" actually do? (one full example)

The mechanics get hand-wavy fast. Let's walk through ONE training example end-to-end with the actual tensors the model sees. Take a sentence and pick one position to hide:

original sentence:   "the cat sat on the mat"
positions:             0    1   2   3   4   5
                              ↑
                              we randomly pick this one

Two things happen at the same instant: we save the word at position 2 (that's our answer key), and we replace it with a special placeholder token called <mask>.

                       0     1     2          3    4     5
input the model sees:  the   cat   <mask>   on   the   mat
saved as answer (label):                  sat      ← we know this; we just hid it

The <mask> is a real word in our vocabulary (a placeholder we added on purpose — id 1 in our 8-word vocab). The model knows position 2 exists, sees the placeholder, and has to guess what was there using only the surrounding words. It never sees sat during the forward pass.

To answer Fernando's son's question directly:

  • Yes — the hidden word becomes the label (the y). We save it aside and grade the model against it. Exact same role as y_true in Lesson 1's regression.
  • No — attention does not depend on the mask position in a special way. Attention always looks at every word's vector. The model produces a guess at every position; we only score it at the masked one.

How the model "guesses" only one position

Transformers produce one output per input token (every position gets a guess). But for this training example we only care about position 2. The way PyTorch is told that is with a labels array the same length as the input, where every position has either the true word id OR the magic value -100 (which means "skip this one"):

                       0      1      2       3      4      5
input ids:             [the]  [cat]  [mask] [on]   [the]  [mat]
labels:                -100   -100   sat     -100   -100   -100
                                       ↑
                                       only this position counts

Cross-entropy loss reads that array: "ignore the -100 positions; at position 2 the right answer is sat — grade me on whether I put high probability on sat there." The five -100s are why the model isn't penalised for being uncertain about the words it was already shown.

So the workflow per training example is exactly:
  1. Pick a random sentence, pick a random position.
  2. Save the word at that position → that becomes the label (y).
  3. Replace the word in the sentence with <mask> → that becomes the input (x).
  4. Run the model. It outputs a guess at every position (because that's how transformers work). We only look at the masked position.
  5. Cross-entropy between the model's guess at the masked position and the saved label → loss → nudge.
Everything else in this lesson is just code that does these 5 steps in a loop.
🧪 Now you do it
Build a training example yourself. Pick a sentence and a position to hide — the code runs live every time you change a value. This is exactly what one training round does inside make_example() in the notebook.
# Build ONE training example by hand
sentence = "the cat sat on the mat"
hide_pos = 2

words  = sentence.split()
ids    = [tok2id[w] for w in words]      # tokenise → list of integer ids

answer = words[hide_pos]                # save the truth — this is the LABEL (y)
labels = [-100] * len(ids)              # -100 = "don't grade this position"
labels[hide_pos] = ids[hide_pos]        # only the hidden position holds the answer

ids[hide_pos] = tok2id["<mask>"]    # replace word with <mask> in the INPUT (x)

print(f"input ids: {ids}")
print(f"labels:    {labels}")
print(f"answer:    {answer}")

That's the data trick. But there's a deeper trick: to get good at this game, the model is FORCED to learn the structure of language.

Think about what the model has to figure out to guess sat in "The cat ___ on the mat":

  • The word "cat" should mean something animal-ish (so the model knows we're talking about a creature) → that pushes the embedding for "cat" to live near other animal embeddings.
  • The blank should pay attention to "cat" and "mat" (the words around it) → that pushes attention to focus where it matters.
  • The model needs some sense of grammar ("cat ___ on" is a verb spot) → that gets baked into the feed-forward layers.

So masking isn't really about filling in blanks. It's a scoreable task that secretly forces the model to learn everything we wanted it to learn — meaningful embeddings, useful attention patterns, grammatical structure. All as a side effect of winning the game.

That's the foundation-model idea. Train on fill-in-the-blank with billions of sentences and you end up with a model that "understands language" enough to be reused for anything: sentiment analysis, summarisation, churn prediction (L5b), fraud detection (L6). One game shapes a model; one model serves many tasks.

How the model plays the game (step by step)

  1. Tokenise + embed (L2) — each word becomes a vector of numbers.
  2. Attention (L3) — the masked vector "looks at" surrounding words and absorbs their context. After attention, the mask vector has a flavour like "small-furry-animal".
  3. Feed-forward (L1.5) — Linear → GELU → Linear refines the per-token vector. (In real Transformers, attention + feed-forward repeat 18 times.)
  4. Predict — score every vocab word, pick the best.
  5. Compare + nudge (L1) — loss.backward(), opt.step(), repeat.

Step 1 Vocabulary and the secret rules

8 words. 3 hidden rules the model must rediscover from masked examples.

vocab  = ["<pad>", "<mask>", "dog", "cat", "fish",
          "bark", "meow", "swim"]
PAIRS  = [("dog", "bark"), ("cat", "meow"), ("fish", "swim")]

Step 2 Build one training example by hand

Pick a pair, randomly choose which slot to hide, replace it with <mask>, remember the true answer.

animal, sound = random.choice(PAIRS)   # e.g. ("dog", "bark")
ids = [tok2id[animal], tok2id[sound]]  # [2, 5]
labels = [-100, -100]                  # -100 = "don't score this position"
hide = random.choice([0, 1])
labels[hide] = ids[hide]               # remember real answer
ids[hide]    = tok2id["<mask>"]      # hide it
# → ids = [1, 5], labels = [2, -100]    "predict dog at position 0"

Step 4 Cross-entropy loss, by hand

Cross-entropy is the loss for when the model is picking from a list of choices (here: "which of the 8 vocab words?"). For each masked position the model outputs a score per word, softmaxes them to probabilities, and the loss is −log(probability it gave the RIGHT answer). It looks only at how much probability landed on the truth.

Make it concrete. The hidden word is bark.
  • Model says bark is 80% likely → loss = −log(0.80) ≈ 0.22  😀 small
  • Model says bark is 30% likely → loss = −log(0.30) ≈ 1.20  😐 medium
  • Model says bark is 2% likely → loss = −log(0.02) ≈ 3.91  😖 big
So the loss is small when the model was confident and right, and blows up when it was sure of the wrong thing. Training pushes probability onto the true word.
Why not MSE? MSE is for predicting a number (how far off is the guess?). Here we're predicting a word — a discrete choice — so "how far off" makes no sense. Cross-entropy measures "how much did you believe the right answer?" instead.

Step 5 Build the tiny model

Before the code: here's one masked sentence flowing all the way through. Each box transforms the data — the shape tells you what changed.

The entire architecture is three lines of code. You've seen each piece in earlier lessons.

class TinyMLM(nn.Module):
    def __init__(self):
        super().__init__()
        self.emb  = nn.Embedding(V, 16)                              # L2
        self.enc  = nn.TransformerEncoderLayer(16, 2, 32,            # L3 + L1.5
                                              batch_first=True)
        self.head = nn.Linear(16, V)                                 # predict word
    def forward(self, x):
        return self.head(self.enc(self.emb(x)))
ComponentOriginWhat it does
nn.Embedding(V, 16)L2Token id → 16-number vector
nn.TransformerEncoderLayer (attention)L3Q/K/V + softmax — tokens look at each other
nn.TransformerEncoderLayer (feed-forward)L1.5Linear → GELU → Linear, per token
nn.Linear(16, V)—Vector → score per vocab word

Step 6 What does the model say BEFORE training?

Random weights → random predictions. On 8 vocab words the expected loss is log(8) ≈ 2.08. The notebook prints the model's confidence on a sample masked input — it's uniform-ish across all 8 words. The model knows nothing yet.

Step 7 Train, with predictions inspected at checkpoints

Same 5-line loop you've used since L1. The only thing that's new is the model in the middle.

for step in range(500):
    batch = [make_example() for _ in range(32)]
    ids, labels = zip(*batch)
    x = torch.tensor(ids); y = torch.tensor(labels)

    logits = model(x)                                      # 1. guess
    loss   = loss_fn(logits.reshape(-1, V), y.reshape(-1)) # 2. wrongness
    opt.zero_grad()                                        # 3. clear
    loss.backward()                                        # 4. gradients
    opt.step()                                             # 5. nudge ALL knobs

Step 10 What did the embeddings learn?

After training, the 16-dim embedding vectors for dog and bark have moved closer together than at random init — because the model needs them to be predictable from each other. Same for cat/meow and fish/swim. The training game taught the embeddings what's related to what.
