Lesson 1 — How a model learns

Before transformers, before any of the fancy stuff: what does "learning" actually mean?

A model is just:

  1. A bag of numbers (the "weights" or "knobs").
  2. A rule for combining those numbers with input to produce an output.

Training means: show it examples, see how wrong it is, nudge the numbers to be less wrong, repeat thousands of times. That's the whole game.

The simplest model in the world

Two knobs (w and b), one rule: y = w · x + b.

The data below comes from a secret rule — y = 2x + 1 — that the model doesn't know. Its job is to figure that rule out by looking at example pairs.

Try it. Move the w and b sliders below. Watch the blue line shift. Try to align it with the green points (the truth). When you're close, the loss number gets small. Then hit Auto-train and let the model find it itself.

The 5 lines that ARE machine learning

Behind that "Auto-train" button is exactly this loop (in PyTorch). It is identical for any model — a linear regression, an embedding, a Transformer, anything with trainable knobs.

for step in range(1000):
    y_pred = w * x + b                       # 1. guess
    loss   = ((y_pred - y_true) ** 2).mean() # 2. how wrong?
    opt.zero_grad()                          # 3. clear old notes
    loss.backward()                          # 4. which way is "less wrong"?
    opt.step()                               # 5. nudge w and b a little

Memorise these five lines. You will see them again — unchanged — in Lesson 2, Lesson 4, and PRAGMA itself.

Walking through it line by line

The data

x      = torch.tensor([1., 2., 3., 4., 5., 6., 7., 8.])
y_true = 2 * x + 1   # the rule the model never sees

Eight examples. The model only sees x and y_true — never the formula.

The knobs

w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)

Two numbers. Both start at 0 — totally wrong. The requires_grad=True flag tells PyTorch "these are the knobs to turn".

The optimiser

opt = torch.optim.SGD([w, b], lr=0.05)

SGD = Stochastic Gradient Descent. It just walks downhill on the loss landscape. The lr is the size of each step.

The loss

For step 0 (with w=0, b=0), the model predicts all zeros. The truth is [3, 5, 7, 9, 11, 13, 15, 17]. The errors are [-3, -5, -7, ...], squared: [9, 25, 49, ...], averaged: 62.5. (Slightly different from the 8-point widget here, which uses the first 5 points for simplicity.)

Why squared? Squaring (1) makes all errors positive and (2) penalises big mistakes more than small ones. A miss of 10 contributes 100 to the loss; a miss of 1 contributes only 1.

The three magic lines

  • opt.zero_grad() — clear last step's notes about which way to nudge.
  • loss.backward() — PyTorch computes the gradient of the loss with respect to w and b. The gradient says "if I increase this knob by 1, how does the loss change?"
  • opt.step() — nudge each knob in the direction opposite its gradient (because we want loss to go down).

For more on why this works, see Lesson 1c, where we open up gradient descent and compute the gradients by hand.

The big takeaway

Three sentences. Memorise these:
  1. A model is a bag of numbers.
  2. Training is nudging those numbers to make guesses more correct.
  3. PyTorch computes which way to nudge them, automatically, no matter how many numbers there are.

That's it. Everything else in this course is decoration.
