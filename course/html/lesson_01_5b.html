Lesson 1.5b — What goes into a neural network

A number, an image, a word — how anything becomes the list of numbers a net can read.

← L1.5 (the single-number net) → L1.6 (stacking into depth)

On Lesson 1.5 the input was always a single number x. Real inputs are bigger — a photo has thousands of pixels, a word has no number at all. The fix is always the same move: turn the thing into a list of numbers and feed that list in. The list's length is all that changes — and it sets the width of the first weight matrix. Let's see it.

Inputs What actually goes IN — turning things into numbers

On Lesson 1.5 the input was always a single number x. But how does an image, or a word, get in? And here is the question that trips everyone up: the number 3 is stored as 32 bits — do those bits go in one per neuron? No. Clearing this up is the key to how everything gets into a net.

A neural net only eats a list of numbers (a vector). The length of that list is the number of features — one slot per real, separate thing about the input. The bits inside each number are just how it's stored; they are never the inputs.

  • A single number (our x): the list has length 1. That one number is fed to every neuron. Not 32 — the bits don't count as inputs.
  • An image: one number per pixel (how bright it is). A 28×28 photo becomes a list of 784 numbers.
  • A word: letters aren't numbers, so we hand each word its own short list of numbers and let training tune them. That learned list is called an embedding — the whole of Lesson 2.

The non-obvious bit: when is something ONE input, and when is it MANY?

A single number like x is one input when its size is the meaning — a thermometer reading of 23 really is "a touch more than 22". One genuine quantity → one slot → x → … → Y.

But 8 black-and-white pixels are 8 separate facts about 8 separate places. "So why not pack them into one number 0–255?" You could — p₁·128 + p₂·64 + … + p₈·1 — but it wrecks the meaning three ways:

  • it secretly declares pixel 1 is worth 128× pixel 8 — an importance order the image never had;
  • flip pixel 1 and the number jumps by 128; flip pixel 8 and it nudges by 1 — so "close numbers" stops meaning "similar pictures";
  • the net then gets one weight for the whole byte, so it can never learn "pixel 3 matters, pixel 7 doesn't." It's stuck.

That packed number is an ID, not a measurement — like turning 8 light switches into a single "score" and handing someone only the score: they can't tell which switches are on, and a bigger score doesn't mean a brighter room. So the rule, brought to earth: one quantity whose magnitude means something → one input; a bag of separate things → one input each. A photo is 784 separate brightness readings → 784 inputs, never one giant number.

The rule: features are the inputs, not bits. The input list has one slot per number / per pixel / per embedding-value — and every slot wires into every neuron of the first layer. That's why you never need "one neuron per bit." Up next in Lesson 2: how words get their lists of numbers.
So why does Lesson 2 encode a word as an integer? (Connecting the two.)

This looks like a contradiction — we just said don't cram separate things into one number, yet a word gets a single integer. Here's the resolution. A word like "cat" first gets a number, say 5342. But that integer is a name / row-number — an ID, not a measurement (exactly the kind we just said you must not feed in directly: 5342 isn't "bigger" than 17, and "cat" isn't 313× "the").

So the net never sees that integer. The ID is only an address: it looks up row 5342 of a big embedding table, which hands back a list of d real numbers — and those are meaningful (each a learned coordinate of the word's meaning) and trainable.

"cat"  →  ID 5342 (just a label)  →  look up row 5342  →  [0.6, −0.2, 0.9, …] (the embedding — a length-d vector, the real input)

So it's the same story as the pixels, just with a lookup bolted on the front: a picture is already numbers, so you flatten it to a vector; a word is not, and its ID is meaningless, so you look it up to get a vector. Either way the net eats a list of d meaningful numbers — never a bare ID, never a packed byte. That lookup table is the embedding, and Lesson 2 is all about learning it.

Picture vs word — two routes to the very same thing (a length-d vector):
🖼 A picture — already numbers
Each pixel is a brightness number, so you just flatten the grid into one list. No lookup needed.
grid  →  flatten  →  [1, 0, 1, …]
🔤 A word — not numbers
Letters aren't numbers, and its ID is a meaningless label — so you look it up in the embedding table to get a list of numbers.
"cat"  →  ID 5342  →  look up  →  [0.6, −0.2, …]

Both arrive at the same place: a length-d vector of meaningful numbers — the net's actual input. A picture is already there; a word needs the lookup to get there.

Row One neuron = one row of weights

Remember the OR neuron back on L1.5? It took two inputs, A and B, and gave each one its own weight. That's the rule: a neuron reading a d-number input needs d weights — exactly one per input number. Lay those weights out in a row:

AB
input — a 2×1 column
= 1·A + 1·B, then add the bias and ReLU.

That "multiply each matching pair, then add them up" is called a dot product. So: one neuron = one dot product of its weight-row with the input column. A 1-input neuron has a 1-long row; the OR neuron a 2-long row; an image neuron a 784-long row. The row length always equals d, the input width.

🤔 “Why two inputs — why not one number with 2 bits (0–3)?”

Because A and B are two separate facts (two switches), and we want the neuron to weigh each one on its own. Two input slots → two weights (wA, wB) → the neuron can say “A counts +1 and B counts +1” (OR), or “only A matters”, or anything in between.

Pack them into one number instead — say 2·A + B, giving 0, 1, 2, 3 — and the neuron gets one weight for the whole thing. It can only stretch that single number; it can’t pull A’s effect apart from B’s. Worse, the packing invents a fake ordering: it claims “A-on (=2) is bigger than B-on (=1)”, but they’re just two independent switches — there’s no real “bigger”.

So the rule from the bits section flips around neatly: the bits inside one number are just storage of one fact (never inputs); but genuinely separate facts each get their own input slot — one weight apiece. (Honest nuance: for plain OR you could just about get away with the packed number — “fire if > 0” — but for a trickier pattern like XOR even that breaks, and either way you’ve thrown away the neuron’s ability to judge each fact on its own.)

Matrix A layer = a stack of rows = a matrix

A layer is just several neurons side by side, each with its own weight-row. Stack the rows and you get a grid of numbers — a matrix. Here are two neurons reading the same two inputs (one tuned for OR, one for AND):

1111
W₁ — 2 rows × 2 columns. Row 1 = OR neuron, row 2 = AND neuron.

The matrix has two dimensions, and each comes from a completely different place:

  • Columns = inputs (d) — one column per input number. The data sets this: 1 for our curve, 2 for A,B, 784 for an image.
  • Rows = hidden neurons (H) — one row per neuron. You set this (next section).

A weight matrix is therefore always H rows × d columns — written H×d.

Choice Where does the number of hidden units come from?

This is the part that surprises people: you pick it. The input width d is forced on you by the data — a photo has 784 pixels, full stop. But the number of hidden neurons H is a dial you turn when you design the net.

Each hidden neuron is one little detector — or, for our curve, one bend. So the dial trades off:

  • more hidden units → more patterns the layer can spot, more bends to fit a wiggly curve — but more weights to train;
  • too few → the layer can't capture the shape (one bend can't make a U);
  • it's a knob you tune by trying — the data doesn't decide it.

Our curve net used H=6; the OR/AND layer above used H=2; one layer of real BERT uses H=3072. Same idea, different dial setting.

Multiply The multiply: rows and columns must line up

Running the whole layer at once is one matrix multiply: the weight matrix W₁ times the input column x. There's exactly one rule — the matrix's columns must equal the vector's rows. The two inner numbers have to match; then they cancel and tell you the output size:

W₁ [2×2]  ·  x [2×1]  =  z [2×1]   — the inner 2s match (legal!), and cancel → result is 2×1.

d = how many numbers go in (the data sets it). H = how many hidden neurons (you choose). The matrix W₁ is always H rows × d columns.
“So when is it 2 input nodes, and when 1?” The number of input nodes = how many numbers describe one example (its features), set by the problem: the logic gate took 2 (A,B), the curve-fitter takes 1 (x), an image takes 784. That count is the d — the matrix's column count. The number of rows is H, which you choose. Two dials, two dimensions.

Detect What does each neuron actually detect?

Time to see a whole net put it together. This one has exactly the shapes you just built: input width d=6 (a 6-pixel strip) and H=4 hidden neurons — so its first weight matrix is 4×6. Watch the same row-times-vector happen on real wires.

Here's the intuition that makes neural networks click: each hidden neuron is a little detector that fires when it spots its pattern (its weight-row matches the input), and the output neuron tallies their votes into the answer Y. Trace one signal all the way through input → hidden → output.

The input vector X is a tiny 6-pixel strip — each pixel on (1) or off (0), so d=6. We've hand-wired this net to answer one question: is the bright part in the centre? Toggle pixels and follow the wires.

🎚 Trace the signal from X to Y

Each hidden neuron looks at 2 pixels and fires (outputs 1) only when both are on: h = ReLU(pixel + pixel − 1). The output neuron adds up their votes with its own weights: Y = 1·h₁ + 3·h₂ + 1·h₃ − 2·h₄. The faint dashed wires are connections with weight 0 — every neuron does connect to every pixel (a full 4×6 matrix), it just ignores four of them.

We hand-wired the weights so you can trace every step. A trained network learns its own weights — usually messier — but the flow is identical: signal X → multiply by weights & ReLU → hidden outputs h → multiply by weights → output Y. Stack layers (next lesson) and later neurons detect features built from earlier ones.

“But each neuron only touches 2 pixels — didn't a layer use the full H×d matrix?”

It does, and this net obeys that exactly — it's just a 4×6 matrix (H=4 detectors × d=6 pixels). A detector that "only looks at 2 pixels" simply has weight 0 on the other four, so we didn't bother drawing those wires. Here's the real W₁ — each row is one detector, 1 = looks here, faint 0 = ignores:

So “sparse wiring” is just zeros in the matrix. The layer is still the same W₁·X you built two sections up: [4×6] · [6×1] = [4×1], one number per detector. (A trained net usually fills those zeros with small non-zero numbers — every neuron ends up listening a little to every pixel. We zeroed them by hand only to keep the picture readable.)

What can 6 numbers actually stand for? (Grounding d=6.)

Six inputs = six separate facts about one thing. Small, but plenty of real problems live right here:

  • A house → [bedrooms, bathrooms, size, age, distance-to-centre, garden?] → predict its price. (That's literally Lesson 5a.)
  • A day's weather → [temp, humidity, wind, pressure, rain, cloud] → predict tomorrow.
  • A person's day → [steps, sleep, resting-HR, calories, active-mins, weight] → flag "unusual day".
  • A tiny image → a 2×3 grid of 6 pixel-brightnesses (our strip is just 1×6).

The recipe never changes — only d grows. A phone photo is d ≈ 150,000 (pixels × 3 colours); one word's embedding is d ≈ 768 in a real model. Same W·x + bias → ReLU, just a much wider matrix. You've now seen the whole machine at d=1, d=2 and d=6 — the big ones work exactly the same.

✅ You can now say…
  • A neural net's input is a list of numbers (a vector) — one slot per feature, never one per bit.
  • A single number is a length-1 list; an image is one number per pixel; a word gets a learned list called an embedding.
  • The input length d sets the width of the first weight matrix (W₁ is hidden×d), and every input number feeds every neuron.
  • Each hidden neuron is a little detector; the output neuron tallies their votes into Y.
