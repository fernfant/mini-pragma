The next-word game (vs fill-in-the-blank)

In Lesson 4 we built TinyMLM. It plays fill-in-the-blank: hide a word in the middle of a sentence, let the model peek at the words on both sides, and guess the missing one. That's how BERT (and PRAGMA) train.

ChatGPT plays a different game: predict the very next word. It only sees the words before the gap — never the future — so it can keep going forever: guess a word, add it, guess the next, add it… That's how it writes whole paragraphs.

The punchline of this whole page: the two games run on the same five-stage pipeline (embed → attention → feed-forward → head → softmax). To turn the fill-in-the-blank model into a writer, we change exactly two small things:
  1. add a causal mask so each word can only look left (Step 5), and
  2. train on shifted labels — "predict the next token" instead of "predict the masked token" (Step 7).
Everything else you already built in L1–L4 stays identical.

Step 1 Free training data, again

Just like masking, next-word prediction needs no human labels. Any text is already training data: for every word, the "right answer" is simply the word that came next. One sentence gives you many examples:

Step 2 Vocabulary + three special tokens

Collect every distinct word, sort it, and add three helpers the model needs:

TokenJob
<pad>Filler, so all sentences can be the same length in a batch.
<bos>"Beginning of sentence." Start every sentence with it, so the model has something to look at when predicting the first real word.
<eos>"End of sentence." The model learns to predict this when the sentence is done — that's how it knows when to stop writing.
 
words  = sorted({w for s in sentences for w in s.split()})
vocab  = ["<pad>", "<bos>", "<eos>"] + words
tok2id = {w: i for i, w in enumerate(vocab)}
Why <eos> matters for a writer but not for TinyMLM: fill-in-the-blank always has a fixed sentence, so it never needs to decide "am I done?". A next-word writer makes that decision every single step — predicting <eos> is literally the model choosing to put down the pen.

Step 3 Tokenise: words → ids

Computers do maths on numbers, not letters. encode() wraps a sentence with <bos>/<eos> and swaps each word for its id. Try it:

Step 4 Why order matters: position embeddings

Here's a subtlety. Attention (L3) treats its inputs like a bag — it has no built-in sense of order. To attention, "dog bites man" and "man bites dog" look the same! For fill-in-the-blank that's often survivable; for writing, word order is everything.

The fix is delightfully simple: we keep a second little embedding table indexed by position (slot 0, slot 1, slot 2…), and add it to the word embedding. Now each vector carries "what word I am" and "where I sit."

word vector ("cat")          [ 0.85, -0.73, -1.49, ... ]
+ position vector (slot 2)   [ 0.10,  0.44, -0.07, ... ]
─────────────────────────────────────────────────────────
= what goes into attention   [ 0.95, -0.29, -1.56, ... ]   ← "cat, in slot 2"

Step 5 The causal mask (no peeking right)

This is the idea that turns a reader into a writer. When the model predicts the word in slot 3, it must use only slots 0–2. If it could see slot 3 (the answer) or slot 4 (the future), it would cheat — and it could never generate, because at writing time the future doesn't exist yet.

We enforce this with a causal mask: a rule that blocks every position from attending to positions on its right. Toggle it below and watch the attention grid change.

🔒 Causal mask: grid cell = "row word looks at column word"
Read the grid: with the mask ON it's a staircase (lower triangle) — slot 3 sees slots 0,1,2,3 but nothing later. That's GPT/our writer. With the mask OFF every cell is open — every word sees every word, including the future. That's BERT/TinyMLM (fine, because it's filling a fixed blank, not generating).

Step 6 Build the model, line by line

Almost identical to TinyMLM. The only additions are the position embedding (Step 4) and the causal mask (Step 5). Here's the whole machine on one picture — follow the arrows top to bottom, that's the path one sentence takes:

Now the same machine as code — read it next to the lessons each line came from:

class NextWord(nn.Module):
    def __init__(self, d=32):
        self.tok  = nn.Embedding(V, d)          # word id  → vector       (L2)
        self.pos  = nn.Embedding(MAXLEN, d)     # position → vector       (Step 4)
        self.enc  = nn.TransformerEncoderLayer(d, nhead=4,
                                               dim_feedforward=64,
                                               batch_first=True)  # attention + FFN (L3 + L1.5)
        self.head = nn.Linear(d, V)             # vector → score per word

    def hidden(self, x):
        T   = x.size(1)
        pos = torch.arange(T).unsqueeze(0)
        h   = self.tok(x) + self.pos(pos)                 # embed + position
        mask = nn.Transformer.generate_square_subsequent_mask(T)  # causal: no peeking right
        return self.enc(h, src_mask=mask)                 # contextualised vectors

    def forward(self, x):
        return self.head(self.hidden(x))                  # one score per vocab word, per slot

Step 7 Train: shift the labels by one



The data trick is even simpler than masking. For a sentence, the input is everything except the last token, and the target is everything except the first — shifted left by one. So at each slot the model must name the next token:



input : <bos>  the   cat   sat   on    the   mat
target:  the    cat   sat   on    the   mat  <eos>
          ↑ predict each word from everything to its LEFT



We score with the same cross-entropy from L4 Step 4 (softmax → −log of the truth), ignoring <pad>. Same 5-line loop you've used since L1:



for step in range(800):
    inp, tgt = X[:, :-1], X[:, 1:]                  # shift by one
    logits = model(inp)                             # 1. guess every next word
    loss = F.cross_entropy(logits.reshape(-1, V),
                           tgt.reshape(-1),
                           ignore_index=PAD)         # 2. how wrong?
    opt.zero_grad(); loss.backward(); opt.step()     # 3-5. clear, gradients, nudge

Step 8 Generate: the actual ChatGPT loop



Now the payoff. To write, we: (1) run the model on the words so far, (2) take its prediction for the last slot, (3) append that word, (4) repeat — until it predicts <eos>. That's the whole trick behind every chatbot.

  And PRAGMA? PRAGMA is the fill-in-the-blank flavour (like TinyMLM) trained on banking events instead of words — its "vocabulary" is things you do (a transfer, a card tap, a login), and its "sentence" is your activity stream. But the machinery on this page — embed, attention, feed-forward, head, softmax, cross-entropy, the training loop — is exactly the same. One pipeline, many games.
