Part A · model.py

The network — same pipeline as 4g, grown-up recipe

One file defines the whole GPT. Read top to bottom it's: a config of dials, then the three building blocks (attention, feed-forward, the block that wires them), then the full model, then named presets.

model.py · the dials
GPTConfig — the GPT-3 family table, as code

Every weight that separates "tiny laptop GPT" from "GPT-3 175B" lives here. Change these numbers and nothing else, and you slide along the whole family.

@dataclass
class GPTConfig:
    block_size: int = 256      # context length (how many tokens it sees at once)
    vocab_size: int = 50257    # tiktoken gpt2 BPE vocabulary
    n_layer: int = 6
    n_head: int = 6
    n_embd: int = 384          # d_model — the "width" of every vector
    dropout: float = 0.1
    bias: bool = True

The 4 dials you turn to grow a GPT

n_embd (width): 384 here → 768 in GPT-3 Small → 12,288 in 175B.
n_layer (depth): 6 here → 12 → 96.
n_head (attention heads, see L4h): 6 → 12 → 96.
block_size (context): 256 here → 2048 in every real GPT-3.
Same class, same forward pass — only the numbers move.

model.py · attention
CausalSelfAttention — every token looks left only

Q, K, V are computed in one matmul, then split into n_head parallel heads. scaled_dot_product_attention(is_causal=True) does the fast, fused attention with the triangular mask baked in — the same mask you built by hand in Lesson 4, now one flag.

class CausalSelfAttention(nn.Module):
    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.c_attn(x).split(self.n_embd, dim=2)   # q,k,v in one go
        # (B, T, C) -> (B, nh, T, hd): split C across the heads
        q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        y = F.scaled_dot_product_attention(
            q, k, v, is_causal=True,                 # <- the causal mask
            dropout_p=self.dropout if self.training else 0.0)
        y = y.transpose(1, 2).contiguous().view(B, T, C)     # re-join the heads
        return self.resid_dropout(self.c_proj(y))

is_causal=True = this triangle (token 4 can't peek at 5)

model.py · the block
MLP + Block — think alone, then the pre-LayerNorm wiring

The MLP is a 2-layer net, 4× wider in the middle, with GELU (the smoother cousin of ReLU). The Block wires attention + MLP with pre-LayerNorm and a residual add: normalise, run the sublayer, add the result back onto the input.

class MLP(nn.Module):
    def forward(self, x):
        return self.dropout(self.c_proj(F.gelu(self.c_fc(x))))   # wide -> GELU -> back

class Block(nn.Module):
    # pre-LN: x = x + attn(ln(x)); x = x + mlp(ln(x))
    def forward(self, x):
        x = x + self.attn(self.ln_1(x))   # 1. look at neighbours
        x = x + self.mlp(self.ln_2(x))    # 2. think alone
        return x

x = x + sublayer(ln(x)) — the residual highway

x→ ln_1→ attn+x→ ln_2→ mlp+x→ out

The +x is the residual connection: each sublayer only has to learn a small correction, and gradients flow straight down the highway. Stacking n_layer of these blocks is the entire depth of a GPT.

model.py · the model
GPT — embeddings → blocks → head, with weight tying

Tokens and positions are embedded and added, run through the stack of blocks, normalised once more, then projected to a score per vocabulary word. The clever bit: the output head shares its weights with the input embedding table (weight tying) — fewer parameters, better results.

self.lm_head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
self.transformer.wte.weight = self.lm_head.weight   # weight tying

def forward(self, idx, targets=None):
    pos = torch.arange(T, device=idx.device)
    x = self.transformer.drop(self.transformer.wte(idx) + self.transformer.wpe(pos))
    for block in self.transformer.h:        # the stack of Blocks
        x = block(x)
    x = self.transformer.ln_f(x)
    if targets is not None:
        logits = self.lm_head(x)
        loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss                 # training: score + how-wrong
    return self.lm_head(x[:, [-1], :]), None  # inference: only the last position

It's the Lesson 4 pipeline exactly: embed → attention → feed-forward → head → softmax, with the loss being the same cross-entropy. The "scores" are logits; softmax turns them into next-token probabilities.

model.py · generate
generate — write one token at a time

To write, we keep feeding the model its own output. Each step: take the last block_size tokens, get logits for the next one, divide by temperature (lower = safer, higher = wilder), keep only the top-k candidates, sample one, append, repeat.

@torch.no_grad()
def generate(self, idx, max_new_tokens, temperature=0.8, top_k=200):
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -self.cfg.block_size:]      # last block_size tokens
        logits, _ = self(idx_cond)
        logits = logits[:, -1, :] / temperature
        v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
        logits[logits < v[:, [-1]]] = -float("inf")  # drop unlikely words
        probs = F.softmax(logits, dim=-1)
        nxt = torch.multinomial(probs, 1)             # roll the weighted dice
        idx = torch.cat((idx, nxt), dim=1)
    return idx

Part B · data.py

Text → one long stream of token ids

Training wants numbers, not letters. This file downloads a corpus, runs it through the GPT-2 BPE tokenizer, and saves the ids as compact uint16 binary files that the trainer memory-maps.

data.py · encode
encode_to_bin — words become uint16 ids on disk

The gpt2 vocabulary is 50,257 pieces — under 65,536 — so every id fits in a 2-byte uint16. We tokenise the whole text once and dump the raw array to a .bin file. A 90/10 split gives train and validation streams.

def encode_to_bin(text: str, out: Path):
    ids = ENC.encode_ordinary(text)
    arr = np.array(ids, dtype=np.uint16)   # gpt2 vocab < 65536, fits in uint16
    arr.tofile(out)

def prep_shakespeare(d: Path):
    text = (d / "input.txt").read_text(encoding="utf-8")
    n = int(len(text) * 0.9)               # 90% train, 10% val
    encode_to_bin(text[:n], d / "train.bin")
    encode_to_bin(text[n:], d / "val.bin")

Part C · train.py

The same five-line loop, dressed up

The heart is the loop from Lesson 1 — predict → loss → backward → step → repeat. The grown-up recipe adds: random windows for batches, a cosine learning-rate schedule, AdamW with weight decay, gradient clipping, gradient accumulation, and bf16 on the Apple GPU.

train.py · batches
get_batch — slide a window over the stream

A training example is just block_size tokens (the input x) and the same span shifted one to the right (the target y — i.e. "the next token at every position"). We grab batch_size random windows at once.

def get_batch(data, block_size, batch_size, device):
    ix = torch.randint(len(data) - block_size - 1, (batch_size,))   # random starts
    x = torch.stack([torch.from_numpy(data[i     : i+block_size  ].astype(np.int64)) for i in ix])
    y = torch.stack([torch.from_numpy(data[i+1   : i+1+block_size].astype(np.int64)) for i in ix])
    return x.to(device), y.to(device)

x is the window, y is the same window shifted +1

… To be or not to be that is the question …

blue = the input window x; pink = the next token the model must predict. Every position in the window predicts its next token at once, so one window is really block_size tiny lessons.

train.py · schedule
lr_at — warm up, then cosine-decay the learning rate

The learning rate isn't fixed. It ramps up linearly for warmup steps (so the fresh, random model doesn't get yanked around), then follows a smooth cosine curve down to min_lr. This is the exact schedule GPT-3 used.

def lr_at(it, lr, warmup, max_iters, min_lr):
    if it < warmup:
        return lr * (it + 1) / warmup                 # linear warmup
    ratio = (it - warmup) / (max_iters - warmup)
    return min_lr + 0.5 * (1 + math.cos(math.pi * ratio)) * (lr - min_lr)   # cosine decay

train.py · optimizer
configure_optimizers — AdamW, decay the matmuls only

AdamW = Adam plus weight decay (gently shrink weights toward zero to curb overfitting). We decay the 2-D weight matrices but not biases or LayerNorm scales — decaying those hurts. betas=(0.9, 0.95) is the GPT-3 setting.

def configure_optimizers(self, weight_decay, lr, betas):
    decay   = [p for p in self.parameters() if p.dim() >= 2]   # matmuls, embeddings
    nodecay = [p for p in self.parameters() if p.dim() < 2]    # biases, LayerNorms
    groups = [{"params": decay,   "weight_decay": weight_decay},
              {"params": nodecay, "weight_decay": 0.0}]
    return torch.optim.AdamW(groups, lr=lr, betas=betas)
train.py · the loop
The loop — predict, blame, nudge, repeat

Here it is. grad_accum runs several mini-batches before each step so the effective batch is bigger than memory would allow. clip_grad_norm_ caps runaway gradients. Everything inside ctx runs in bf16 on the GPU. Strip the recipe away and it's the Lesson 1 loop.

for it in range(max_iters + 1):
    for g in opt.param_groups:
        g["lr"] = lr_at(it, ...)                 # set today's learning rate

    opt.zero_grad(set_to_none=True)
    for _ in range(grad_accum):              # accumulate over mini-batches
        x, y = get_batch(train_data, ...)
        with ctx:                            # bf16 autocast on MPS
            _, loss = model(x, y)            # predict + measure
            loss = loss / grad_accum
        loss.backward()                      # blame each weight
    torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip)
    opt.step()                               # nudge them all

Part D · sample.py

Generate from a saved checkpoint

Training saves a checkpoint whenever validation loss improves. This file loads one back and writes text from your prompt.

sample.py
Load the checkpoint, rebuild the model, generate

The checkpoint stores both the weights and the cfg dict, so we rebuild the exact same architecture, load the weights, encode the prompt to ids, and call generate.

ck = torch.load(Path(args.ckpt), map_location=device)
model = GPT(GPTConfig(**ck["cfg"])).to(device)   # same dials as training
model.load_state_dict(ck["model"])
model.eval()

ids = ENC.encode_ordinary(args.prompt) or ENC.encode_ordinary("\n")
x = torch.tensor([ids], device=device)
out = model.generate(x, max_new_tokens=args.tokens,
                     temperature=args.temperature, top_k=args.top_k)
print(ENC.decode(out[0].tolist()))
